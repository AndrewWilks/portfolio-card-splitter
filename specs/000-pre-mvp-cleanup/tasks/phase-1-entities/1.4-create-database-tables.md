## Migration SQL

```sql
-- Migration: Add CardAccount and Card support
-- Date: 2025-11-07

-- Create card_accounts table
CREATE TABLE card_accounts (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name VARCHAR(255) NOT NULL,
  issuer VARCHAR(255) NOT NULL,
  last4 VARCHAR(4) NOT NULL,
  billing_cycle INTEGER NOT NULL CHECK (billing_cycle >= 1 AND billing_cycle <= 31),
  credit_limit_cents BIGINT CHECK (credit_limit_cents > 0),
  owner_id UUID NOT NULL REFERENCES users(id) ON DELETE RESTRICT,
  is_active BOOLEAN NOT NULL DEFAULT true,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_card_accounts_owner_id ON card_accounts(owner_id);
CREATE INDEX idx_card_accounts_is_active ON card_accounts(is_active);

-- Create cards table
CREATE TABLE cards (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  card_account_id UUID NOT NULL REFERENCES card_accounts(id) ON DELETE CASCADE,
  member_id UUID REFERENCES members(id) ON DELETE SET NULL,
  nickname VARCHAR(100),
  last4 VARCHAR(4),
  is_active BOOLEAN NOT NULL DEFAULT true,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_cards_card_account_id ON cards(card_account_id);
CREATE INDEX idx_cards_member_id ON cards(member_id);
CREATE INDEX idx_cards_is_active ON cards(is_active);

-- Create default "Legacy" CardAccount for existing transactions
INSERT INTO card_accounts (name, issuer, last4, billing_cycle, owner_id, is_active)
SELECT 'Legacy Account', 'Unknown', '0000', 1, u.id, true
FROM users u
LIMIT 1
RETURNING id INTO @legacy_card_account_id;

-- Add card references to transactions
ALTER TABLE transactions
  ADD COLUMN card_account_id UUID REFERENCES card_accounts(id) ON DELETE RESTRICT,
  ADD COLUMN card_id UUID REFERENCES cards(id) ON DELETE SET NULL;

-- Assign existing transactions to default card account
UPDATE transactions
SET card_account_id = @legacy_card_account_id
WHERE card_account_id IS NULL;

-- Make card_account_id NOT NULL after data migration
ALTER TABLE transactions
  ALTER COLUMN card_account_id SET NOT NULL;

-- Create indexes
CREATE INDEX idx_transactions_card_account_id ON transactions(card_account_id);
CREATE INDEX idx_transactions_card_id ON transactions(card_id);
```

## Rollback SQL

```sql
-- Rollback: Remove CardAccount and Card support
-- WARNING: This will delete all CardAccount and Card data

-- Drop transaction indexes
DROP INDEX IF EXISTS idx_transactions_card_account_id;
DROP INDEX IF EXISTS idx_transactions_card_id;

-- Remove card references from transactions
ALTER TABLE transactions
  DROP COLUMN card_account_id,
  DROP COLUMN card_id;

-- Drop cards table
DROP TABLE IF EXISTS cards;

-- Drop card_accounts table
DROP TABLE IF EXISTS card_accounts;
```

## Data Migration Notes

### For Production

1. **Before migration**:

   - Backup database
   - Verify user exists (for default CardAccount owner)
   - Check number of existing transactions

2. **During migration**:

   - Migration creates default "Legacy Account"
   - All existing transactions assigned to it
   - No data loss

3. **After migration**:
   - Users can create proper CardAccounts
   - Users can reassign transactions if needed
   - Legacy Account can be kept or archived

### For Development

- Safe to run fresh (no existing transactions)
- Creates default CardAccount for testing
- Can be rolled back safely
