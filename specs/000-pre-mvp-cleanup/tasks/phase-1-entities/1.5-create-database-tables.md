## Migration SQL

```sql
-- Migration: Add CardAccount, CardAccountSettings, and Card support
-- Date: 2025-11-07

-- Create card_accounts table
CREATE TABLE card_accounts (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name VARCHAR(255) NOT NULL,
  issuer VARCHAR(255) NOT NULL,
  last4 VARCHAR(4) NOT NULL,
  billing_cycle INTEGER NOT NULL CHECK (billing_cycle >= 1 AND billing_cycle <= 31),
  credit_limit_cents BIGINT CHECK (credit_limit_cents > 0),
  owner_id UUID NOT NULL REFERENCES users(id) ON DELETE RESTRICT,
  is_active BOOLEAN NOT NULL DEFAULT true,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_card_accounts_owner_id ON card_accounts(owner_id);
CREATE INDEX idx_card_accounts_is_active ON card_accounts(is_active);

-- Create card_account_settings table (one-to-one with card_accounts)
CREATE TABLE card_account_settings (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  card_account_id UUID NOT NULL UNIQUE REFERENCES card_accounts(id) ON DELETE CASCADE,
  statement_close_day_of_month INTEGER NOT NULL DEFAULT 15 CHECK (statement_close_day_of_month >= 1 AND statement_close_day_of_month <= 31),
  statement_frequency_days INTEGER NOT NULL DEFAULT 30 CHECK (statement_frequency_days > 0),
  payment_due_days_after_close INTEGER NOT NULL DEFAULT 21 CHECK (payment_due_days_after_close > 0),
  interest_free_days INTEGER NOT NULL DEFAULT 55 CHECK (interest_free_days > 0),
  has_interest_free_period BOOLEAN NOT NULL DEFAULT true,
  minimum_payment_percentage NUMERIC(5,2) NOT NULL DEFAULT 2.00 CHECK (minimum_payment_percentage >= 0.01 AND minimum_payment_percentage <= 100),
  minimum_payment_floor_cents BIGINT NOT NULL DEFAULT 2500 CHECK (minimum_payment_floor_cents > 0),
  reminder_days_before_due INTEGER NOT NULL DEFAULT 3 CHECK (reminder_days_before_due >= 0),
  is_active BOOLEAN NOT NULL DEFAULT true,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE UNIQUE INDEX idx_card_account_settings_card_account_id ON card_account_settings(card_account_id);
CREATE INDEX idx_card_account_settings_is_active ON card_account_settings(is_active);

-- Create cards table
CREATE TABLE cards (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  card_account_id UUID NOT NULL REFERENCES card_accounts(id) ON DELETE CASCADE,
  member_id UUID REFERENCES members(id) ON DELETE SET NULL,
  nickname VARCHAR(100),
  last4 VARCHAR(4),
  is_active BOOLEAN NOT NULL DEFAULT true,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_cards_card_account_id ON cards(card_account_id);
CREATE INDEX idx_cards_member_id ON cards(member_id);
CREATE INDEX idx_cards_is_active ON cards(is_active);

-- Create default "Legacy" CardAccount for existing transactions
DO $$
DECLARE
  legacy_card_account_id UUID;
  first_user_id UUID;
BEGIN
  -- Get first user
  SELECT id INTO first_user_id FROM users LIMIT 1;
  
  IF first_user_id IS NOT NULL THEN
    -- Create legacy CardAccount
    INSERT INTO card_accounts (name, issuer, last4, billing_cycle, owner_id, is_active)
    VALUES ('Legacy Account', 'Unknown', '0000', 1, first_user_id, true)
    RETURNING id INTO legacy_card_account_id;
    
    -- Create default settings for legacy account
    INSERT INTO card_account_settings (card_account_id)
    VALUES (legacy_card_account_id);
    
    -- Add card references to transactions
    ALTER TABLE transactions
      ADD COLUMN card_account_id UUID REFERENCES card_accounts(id) ON DELETE RESTRICT,
      ADD COLUMN card_id UUID REFERENCES cards(id) ON DELETE SET NULL;
    
    -- Assign existing transactions to legacy card account
    UPDATE transactions
    SET card_account_id = legacy_card_account_id
    WHERE card_account_id IS NULL;
    
    -- Make card_account_id NOT NULL after data migration
    ALTER TABLE transactions
      ALTER COLUMN card_account_id SET NOT NULL;
    
    -- Create indexes
    CREATE INDEX idx_transactions_card_account_id ON transactions(card_account_id);
    CREATE INDEX idx_transactions_card_id ON transactions(card_id);
  ELSE
    RAISE EXCEPTION 'No users found. Cannot create legacy CardAccount.';
  END IF;
END $$;
```

## Rollback SQL

```sql
-- Rollback: Remove CardAccount, CardAccountSettings, and Card support
-- WARNING: This will delete all CardAccount, CardAccountSettings, and Card data

-- Drop transaction indexes
DROP INDEX IF EXISTS idx_transactions_card_account_id;
DROP INDEX IF EXISTS idx_transactions_card_id;

-- Remove card references from transactions
ALTER TABLE transactions
  DROP COLUMN IF EXISTS card_account_id,
  DROP COLUMN IF EXISTS card_id;

-- Drop cards table
DROP TABLE IF EXISTS cards;

-- Drop card_account_settings table
DROP TABLE IF EXISTS card_account_settings;

-- Drop card_accounts table
DROP TABLE IF EXISTS card_accounts;
```

## Data Migration Notes

### For Production

1. **Before migration**:

   - Backup database
   - Verify at least one user exists (for default CardAccount owner)
   - Check number of existing transactions

2. **During migration**:

   - Migration creates default "Legacy Account" CardAccount
   - Default settings created for Legacy Account (Australian CommBank defaults)
   - All existing transactions assigned to Legacy Account
   - No data loss

3. **After migration**:

   - Users can create proper CardAccounts with custom or default settings
   - Users can reassign transactions if needed
   - Legacy Account can be kept or archived
   - **Important**: Application logic must create settings when creating CardAccounts

### For Development

- Safe to run fresh (no existing transactions)
- Creates default CardAccount with settings for testing
- Can be rolled back safely

### Settings Creation Strategy

**Option 1: Application layer** (Recommended for MVP)

- CardAccountService.create() creates both CardAccount and CardAccountSettings
- Transactional - both succeed or both fail
- Explicit control over defaults

**Option 2: Database trigger** (Future enhancement)

```sql
CREATE OR REPLACE FUNCTION create_default_settings()
RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO card_account_settings (card_account_id)
  VALUES (NEW.id);
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trigger_create_default_settings
AFTER INSERT ON card_accounts
FOR EACH ROW
EXECUTE FUNCTION create_default_settings();
```

For MVP, we'll use **Option 1** (application layer).

## Notes

- Check constraints ensure valid ranges (billingCycle 1-31, positive amounts, percentage 0.01-100)
- Foreign keys use proper ON DELETE actions:
  - CardAccount → User: RESTRICT (can't delete user with card accounts)
  - CardAccountSettings → CardAccount: CASCADE (delete settings with card account)
  - Card → CardAccount: CASCADE (delete cards with card account)
  - Card → Member: SET NULL (member deletion doesn't affect card)
  - Transaction → CardAccount: RESTRICT (can't delete card account with transactions)
  - Transaction → Card: SET NULL (card deletion doesn't orphan transaction)
- Unique constraint ensures one-to-one CardAccount ↔ CardAccountSettings
- Default settings match Australian CommBank credit card patterns
- Indexes improve query performance for common access patterns
- Settings provide sensible defaults but can be customized per account
