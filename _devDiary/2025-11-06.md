# Dev Diary Entry - 2025-11-06

## Spec Refinement & Entity Model Updates

Massive rethink of the app today as I came to the realisation that we are missing a key element of the entities being the card itself. Also we are missing specs that reflect the app as a whole with this in mind.

### What We Did

#### **1. Updated High-Level Product Spec**

- Clarified CardAccount vs Card distinction (CardAccount = credit card account, Card = optional physical/virtual card for attribution)
- Added explicit rules for unallocated transactions workflow
- Defined payment-reservation reconciliation behavior (system flags mismatches)
- Documented outstanding balance formula: `sum(transactions) - sum(payments)` per CardAccount
- Clarified multi-member reservation pattern (each member reserves independently against their allocation)

#### **2. Refined Entity Model**

- Added business rule enforcement to `Allocation`: one-of validation for basisPoints vs amountCents
- Updated `Pot` to compute derived values (availableCents, reservedCents) without persisting them to prevent drift
- Made `Transfer` support cash transactions via nullable pot IDs with invariant checking
- Implemented idempotent token/session usage with guards to prevent reuse
- Made internal helpers private, exposed only necessary public APIs

#### **3. Updated Architecture Documentation**

- Aligned with product vision (shared credit card with interest-free arbitrage)
- Clarified shared layer: entities, types, utilities ONLY (repositories are NOT shared)
- Backend repos talk to Postgres, frontend repos talk to API - different concerns
- Simplified domain model organization by domain area
- Updated API endpoints to match MVP scope (auth, pots, reservations, payments, ledger)
- Added "Key Architectural Decisions" section explaining the WHY behind choices

### Key Outcomes

- Product spec now has clear allocation workflow: unallocated → allocated → reserved → paid
- Entity model enforces business rules at construction time (fail fast)
- Shared layer properly scoped to avoid forcing wrong abstractions
- Specs are now portfolio-ready: clear, complete, and ready to guide implementation
